# Регистрация Telegram webhook

Этот скилл предназначен для локального запуска **самим владельцем бота**. У каждого коллеги должен быть собственный Supabase-проект: функция хранит только одну пару `BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET` на проект. Не запускай настройку для общего или рабочего проекта другого человека.

## Перед запуском

1. Убедись, что коллега работает с копией этого репозитория, вошёл в Supabase CLI и имеет права Owner/Admin в **своём** Supabase-проекте.
2. В проекте должна быть развёрнута Edge Function `webhook` из этого репозитория, с маршрутом `/functions/v1/webhook/telegram`, а для тестирования обработки сообщений — применена схема БД и RPC из инструкции проекта. Для функции должен быть отключён JWT-проверочный шлюз (`verify_jwt = false`), так как проверка входящего Telegram-запроса выполняется по секретному заголовку.
3. Попроси подготовить HTTPS-адрес проекта вида `https://<project-ref>.supabase.co` и токен **своего** бота от BotFather. Секрет webhook можно ввести самостоятельно (1–256 символов `A-Z`, `a-z`, `0-9`, `_`, `-`) или оставить поле пустым — скрипт создаст случайный. Не проси присылать токен или секрет в чат, скриншот, файл, переменную окружения или командную строку.
4. В корне репозитория должны быть Node.js и доступный Supabase CLI (из `node_modules/.bin/supabase` или `PATH`). Не устанавливай и не обновляй зависимости без разрешения пользователя.

## Запуск

Из корня репозитория коллега запускает в **своём интерактивном терминале**:

```sh
node .codex/skills/register-telegram-webhook/scripts/register-webhook.mjs
```

Не запускай команду вместо коллеги через инструмент, который записывает ввод или вывод в историю разговора. Не передавай секреты как аргументы, через `echo`, pipe из чата, `.env` или `npm run set-webhook`: старый скрипт читает `.env`.

Скрипт скрыто запрашивает токен и секрет, проверяет доступность функции и бота, показывает публичные сведения о проекте, боте и текущем webhook, затем требует явное подтверждение. После подтверждения он передаёт оба секрета в Supabase CLI через stdin (`--env-file /dev/stdin`), регистрирует адрес с `secret_token` в Telegram и сверяет результат через `getWebhookInfo`. Секреты не записываются в файлы проекта, аргументы процессов или переменные окружения; значение webhook-секрета не показывается повторно.

## Поведение и безопасность

- Целью может быть только стандартный адрес **личного** Supabase-проекта. Скрипт отклоняет известный проект этого репозитория `cappgvetnxvjhnxufhkz`, чтобы коллега случайно не перезаписал его секреты.
- Регистрация на стороне Telegram выполняется **после** успешного сохранения секретов в Supabase. Скрипт не удаляет ожидающие обновления Telegram (`drop_pending_updates` не используется).
- Если CLI или Telegram сообщает об ошибке, не проси переслать полный терминальный лог, токен, секрет или URL Telegram API. Сообщи только этап, на котором произошла ошибка, и проверь не секретные предпосылки: права проекта, вход в Supabase CLI, URL, факт развёртывания функции и доступность Telegram API.
- Если CLI сохранил секреты, а регистрация Telegram не удалась, состояние частично изменено. Повтори запуск со своим токеном: можно ввести прежний секрет или создать новый, тогда он снова будет записан в Supabase перед регистрацией. Не делай автоматический откат неизвестных прежних значений.
- Не вызывай `setWebhook` и не меняй секреты Supabase при простом вопросе, аудите или просьбе объяснить процедуру. Эти записи выполняются только после явного действия коллеги и подтверждения в терминале.

## Результат

Считай операцию успешной только когда `getWebhookInfo` вернул ожидаемый URL. Попроси коллегу отправить `/start` своему боту и проверить фактическую обработку сообщения. Само наличие webhook не доказывает, что миграции БД, RPC и ответы бота работают.

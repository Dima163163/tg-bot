# 0001. Не запускать полный локальный стек Supabase

- Status: Accepted
- Date: 2026-10-08

## Context

Проект работает с управляемыми Supabase-проектами; для личных тестов бота используются отдельные проекты. В репозитории уже есть Supabase CLI-команды для отправки миграций и публикации функций. Команда `npm test` проверяет обработчик webhook и не требует локальной базы Supabase.

Поэтому решение не использовать CLI целиком было бы неточным: за рамками обычного рабочего процесса находится именно запуск полного локального стека через `supabase start`.

## Decision

Не запускать `supabase start` в обычном цикле разработки и проверки. Продолжать использовать CLI для миграций и публикации функций. Существующую `functions:serve` оставить как отдельный способ локально запускать Edge Function; он не означает запуск полного Supabase-стека.

Локальный стек можно пересмотреть, если появятся интеграционные сценарии, которым нужны локальные PostgreSQL, Realtime или другие сервисы Supabase.

## Options considered

- **Запускать полный локальный стек:** не выбран, поскольку текущие тесты webhook и основной сценарий с управляемыми проектами от него не зависят.
- **Оставить управляемые проекты и использовать CLI для нужных операций:** выбранный вариант; он сохраняет миграции и деплой через CLI без отдельного локального окружения Supabase.

## Consequences

- Локальные интеграционные проверки с PostgreSQL и Realtime не входят в текущий тестовый цикл.
- Проверки, которым нужны эти сервисы, выполняются в специально выбранном управляемом проекте либо потребуют отдельного решения о запуске локального стека.
- При выполнении связанных с проектом команд CLI нужно проверять, к какому удалённому проекту привязана конфигурация.
